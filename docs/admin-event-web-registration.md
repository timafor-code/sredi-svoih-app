# Admin Event Web Registration

For eligible events, the canonical web-registration URL appears directly below
the title on the existing web-admin event edit page. Its copy and edit controls,
and the detailed `Веб-страница` tab, share one server-authoritative editor
state. The create-event page still shows a non-interactive notice because a
stable link is available only after the event has an ID.

## Publication modes

- `Выключено` (`disabled`) keeps the public page unavailable to participants.
  The stable link remains visible so an organizer can prepare materials, but
  the admin does not offer to open the unavailable page.
- `Только по ссылке` (`unlisted`) makes the page available to people with the
  direct link and keeps the event out of a general catalog.
- `В каталоге` (`listed`) is post-MVP. If the API returns this future value, the
  admin displays it as a read-only status and does not replace it with another
  value or offer to manage it.

For ordinary admin creation, `internal_free` and `internal_paid` start as
`Только по ссылке`; `none` and `external_link` start as `Выключено`. This direct
link state is the normal setup flow, not a prerequisite selector. An explicit
`Отключить веб-регистрацию` action is confirmed before it sends only
`web_visibility=disabled` to the dedicated endpoint. `Включить веб-регистрацию`
explicitly restores `unlisted`. The setting is not added to ordinary event
create/update payloads. Automatic mode transitions are backend-owned and do not
make an event published.

## Stable links

Absolute URLs are generated by the backend from the backend-only
`PUBLIC_WEB_BASE_URL` setting. Web-admin consumes the authoritative
`public_registration_url` returned by GET/PATCH and never guesses a hostname
from browser location or frontend configuration. Copy and open actions always
use this saved URL, never an unsaved preview.

The header provides an accessible copy icon (`Скопировать адрес веб-регистрации`)
and pencil icon (`Редактировать адрес веб-регистрации`). A disabled address is
muted and cannot be opened, although it can still be copied with an unavailable
warning. The address editor accepts only the suffix after the immutable backend-derived
`/events/` prefix. It checks the entered value after an approximately 400 ms
debounce and immediately on blur through
`POST /admin/events/{event_id}/web-registration/check-slug`. An empty suffix
uses the current saved event title as the explicit preview source. The admin
does not transliterate locally: `normalized_slug` from the backend is the only
preview value.

Availability is advisory. `Сохранить адрес` is a separate explicit action and
the PATCH repeats normalization and collision checks transactionally. A PATCH
`409 public_slug_taken` or `422 invalid_public_slug` overrides an earlier green
preview. After success, the editor, copy action, and open action use only the
returned `public_slug` and `public_registration_url`. The previous canonical
slug remains a working alias. Renaming the event, changing occurrences, or
toggling publication does not change the canonical URL.

The deprecated operator-facing occurrence-link list and `occurrence_urls` admin
response field are removed. Public `?occurrence={uuid}` routing, legacy UUID
routes, occurrence selection, intents, and registrations remain supported.

Web-admin only copies links with the browser Clipboard API or opens an enabled
main link in a new tab. It does not send email, Telegram, WhatsApp, SMS, Web
Share, or any other participant message. While publication is disabled, the
public page remains unavailable even though its stable URL can still be copied.

## Registration questionnaire

The existing event edit page shows the `Анкета регистрации` card immediately
after the web-registration card and before the occurrence editor. It is
admin-only: `event_manager` users do not mount the component and therefore do
not call the questionnaire endpoints. The create-event page does not show the
editor because questionnaire configuration requires an existing event ID.

An admin may prepare a versioned draft using only ordinary organizational
questions. The questionnaire purpose, every question purpose, and every
positive retention period are mandatory. Draft save is explicit and there is
no autosave. Publishing is a separate action with confirmation. The current
published version stays read-only and immutable; when no draft exists, a new
local editor may be prefilled from it without changing the published version.
No sensitive or special-category control is available.

Public questionnaire rendering and submission are intentionally deferred to
`feature/web-event-questionnaires-public-ui`.

## Manual smoke checklist

Manual smoke is performed by the project owner on the pushed PR branch.

1. Create an `internal_free` event and confirm it starts as `Только по ссылке` without a separate enable save.
2. Confirm the canonical URL appears below the saved event title, opens only while enabled, and copies exactly the backend URL.
3. Create an `internal_paid` event and confirm the same default.
4. Create `none` or `external_link` and confirm no active header registration link is shown.
5. Change `none` to `internal_free`, save, and confirm the header URL appears without reload.
6. Confirm the current canonical suffix and immutable prefix are displayed.
7. Use the header pencil: confirm only the suffix is editable, backend normalization/preview works, and cancel restores the saved suffix.
8. Confirm debounce checking and immediate checking on blur, including occupied and invalid values.
9. Save a new slug and confirm both header and tab update immediately; copy/open must use only the saved URL and the prior slug remains an alias.
10. Explicitly disable web registration; confirm the URL becomes muted/non-openable, copying warns that it is unavailable, and unrelated saves preserve disabled.
11. Change disabled `internal_free` to `internal_paid`; confirm it stays disabled, then explicitly re-enable to `unlisted`.
12. Change an internal event to `none`; confirm it becomes disabled and the header controls disappear.
13. Confirm a draft or hidden internal event can be `unlisted` but remains unavailable publicly.
14. Confirm `Ссылки на отдельные даты` is absent while public occurrence selection still works.
15. Check keyboard navigation, live announcements, and a narrow mobile admin width.
16. Open the create-event page and confirm it says the event must first be saved.
17. Confirm no event messages are sent and no catalog management is shown.
