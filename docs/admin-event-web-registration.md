# Admin Event Web Registration

The web-registration block appears on the existing web-admin event edit page,
between the event form and the occurrence editor. It loads the current
publication state and stable public links from the authenticated Python API.
The create-event page shows a non-interactive notice instead because a stable
link is available only after the event has an ID.

## Publication modes

- `Выключено` (`disabled`) keeps the public page unavailable to participants.
  The stable link remains visible so an organizer can prepare materials, but
  the admin does not offer to open the unavailable page.
- `Только по ссылке` (`unlisted`) makes the page available to people with the
  direct link and keeps the event out of a general catalog.
- `В каталоге` (`listed`) is post-MVP. If the API returns this future value, the
  admin displays it as a read-only status and does not replace it with another
  value or offer to manage it.

Changing publication mode is a separate explicit save action. The admin sends
only `web_visibility` to the dedicated
`PATCH /admin/events/{event_id}/web-registration` endpoint; it does not add the
setting to ordinary event create or update payloads.

## Stable links

Absolute URLs are generated by the backend from the backend-only
`PUBLIC_WEB_BASE_URL` setting. Web-admin consumes `public_registration_url` and
`occurrence_urls` exactly as returned and never constructs, edits, or stores a
complete public URL. The main URL uses the current canonical public slug.
Renaming the event, changing occurrences, or toggling publication does not
change it; an explicit slug change does, while the previous slug remains a
working alias.

For recurring events, each deprecated occurrence link uses the canonical event page with an
`occurrence` query value. Opening that link preselects the corresponding date;
the backend remains responsible for verifying that the occurrence belongs to
the event. The admin labels these links with formatted date and time rather
than exposing the occurrence UUID as the primary label.

Web-admin only copies links with the browser Clipboard API or opens an enabled
main link in a new tab. It does not send email, Telegram, WhatsApp, SMS, Web
Share, or any other participant message. While publication is disabled, the
public page remains unavailable even though its stable URL can still be copied.

## Registration questionnaire

The existing event edit page shows the `Анкета регистрации` card immediately
after the web-registration card and before the occurrence editor. It is
admin-only: `event_manager` users do not mount the component and therefore do
not call the questionnaire endpoints. The create-event page does not show the
editor because questionnaire configuration requires an existing event ID.

An admin may prepare a versioned draft using only ordinary organizational
questions. The questionnaire purpose, every question purpose, and every
positive retention period are mandatory. Draft save is explicit and there is
no autosave. Publishing is a separate action with confirmation. The current
published version stays read-only and immutable; when no draft exists, a new
local editor may be prefilled from it without changing the published version.
No sensitive or special-category control is available.

Public questionnaire rendering and submission are intentionally deferred to
`feature/web-event-questionnaires-public-ui`.

## Manual smoke checklist

Manual smoke is performed by the project owner on the pushed PR branch.

1. Open an existing event in web-admin.
2. Confirm the web-registration card loads.
3. Confirm the initial mode is `Выключено` for an event not enabled for web.
4. Confirm the stable read-only URL is displayed.
5. Copy the disabled link and confirm the message also says the page is disabled.
6. Confirm `Открыть страницу` is disabled while publication is off.
7. Change the mode to `Только по ссылке` and save.
8. Reload the event and confirm the mode persists.
9. Copy the main link.
10. Open the main link in a new tab.
11. Confirm the event page loads from `apps/web`.
12. For a recurring event, copy an occurrence-specific link.
13. Open the copied occurrence link manually and confirm the date is preselected.
14. Disable web publication again.
15. Confirm the public page becomes unavailable while the stable URL remains unchanged.
16. Open the create-event page and confirm it says the event must first be saved.
17. Check keyboard navigation and accessible success/error announcements.
18. Confirm no event messages are sent and no catalog is shown.
